## Problem statement

Information Asset Owners want their genomic data used in research, but releasing copies of it to
individual Data Consumers is hard to govern, and asking every Information Asset Owner to run their own
trusted research environment re-creates data silos.

A genomic data node is a **thin, neutral data layer**: Information Asset Owners trust it to cache their data and keep
the authority to decide who may use it, and researcher environments connect to it to use
the data under those decisions.

## System landscape

| Actor  | Interaction                                                                           |
|--------------------------|---------------------------------------------------------------------------------------|
| Information Asset Owner (a.k.a Data Custodian)          | Gives standing permission for data to be cached into a node; approves access applications per project                           |
| Data Consumer (a.k.a. Researcher)             | Does science using data                       |
| Operator  | Coordinates activity in the node for datasets / projects |

| External System  | Interaction                                                                           |
|--------------------------|---------------------------------------------------------------------------------------|
| AAF                      | Australian Access Federation authenticates users with their home institution                                |
| REMS  | Manages data access applications and entitlements  |
| Long Term Data Storage        | Object storage holding the Information Asset Owner's source data     |
| Seqera   | Analysis environment for data consumers                         |
| Globus   | External system that can copy objects from long term data storage to a node (not in production)                         |

## Solution scope

### In scope

- Copying Information Asset Owner datasets into node storage with verified integrity
- A consistent dataset structure
- Serving authorised data to researcher environments (htsget, pre-signed URLs, VPC Lattice)
- Configuring sharing into researcher environments
- Cost estimation and reporting for data movement and storage
- Logging and auditing

### Out of scope

- Making access decisions, this decision-making is upstream and defined by information asset owners
- The setup of access applications, approvals and entitlements (REMS) - except where humans consume data from these
  systems in order to work
- Releasing copies of data to collaborators outside of genomic data nodes - whilst this functionality is supported by
  various components of the system (in particular we use steps-s3-copy to do this where appropriate) we do
  not consider it part of this solution architecture
- Help desk and training
- Setup of compatible researcher environments
