    <p>
        A Terraform provider for managing the content of <a href="https://github.com/CSCfi/rems">REMS</a> (Resource
        Entitlement Management System) instances. REMS is an open-source system that
        manages researcher access requests and entitlements to controlled-access datasets.
    </p>
    <p>
        This provider does <strong>not</strong> install REMS itself — it manages the content of an already-running
        REMS instance. Using it, the entire catalogue of data-access forms, workflows, licences, and resources
        can be version-controlled and deployed as code, giving reproducible and auditable access configurations
        across environments.
    </p>
    <p>
        The provider covers all the objects needed to build an end-to-end access-request workflow:
        <ul>
            <li><strong>Forms</strong> — the questionnaires researchers fill in when applying for access, including
            conditional field visibility</li>
            <li><strong>Workflows</strong> — the approval chains that route applications to the right handlers</li>
            <li><strong>Licences</strong> — data-use agreements attached to catalogue items (inline text or file
            attachment)</li>
            <li><strong>Resources</strong> — the dataset identifiers that REMS tracks entitlements against</li>
            <li><strong>Catalogue items</strong> — the public-facing entries that wire together a resource,
            workflow, form, and category into a single access request listing</li>
            <li><strong>Categories</strong> — groupings used to organise catalogue items in the UI</li>
            <li><strong>Blacklists</strong> — per-resource user blocklists for flagging users to application handlers</li>
        </ul>
    </p>
    <p>
        Connecting to a REMS instance requires an endpoint, an API user, and an API key — all of which
        can be passed as environment variables to keep secrets out of Terraform state. See the provider documentation for
        the full configuration reference.
    </p>

    <h2>Example: creating a licence</h2>
    <p>
        Rather than clicking through the REMS admin UI to create a license, the equivalent
        resource can be declared in HCL and applied with <code>terraform apply</code>:
    </p>

    <Code code={licenceExample} lang="hcl" title="license.tf" />

    <p>
        Running <code>terraform apply</code> with the above creates the corresponding licence entry in the
        REMS admin UI:
    </p>

    <Image src={ExampleTestLicense} alt="REMS admin UI showing the created Test License entry with organization, title, type, licence text, and active status fields" />

    <p>
        Terraform will create the licence in REMS, track it in state, and update or destroy it as
        the configuration changes — giving the same licence definition across all environments without
        manual UI steps.
    </p>
    <p>
        End-to-end runnable examples are included in the repository under <code>examples/usage/</code>,
        covering a simple form, a licence, and a full catalogue item setup that wires all objects together.
    </p>
