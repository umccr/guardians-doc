## Solution Architecture

Firstly, we should note that whilst the requirements for the copy service are somewhat technologically
agnostic – in practice we will need to write and run the service in a particular cloud
or on-prem location. Due to egress and speed concerns, a copy service written to run in AWS
but which can copy objects between Google Cloud buckets – is not the service you would use to copy the Google objects.

To that end, we have documented here *only* a copy service that runs in AWS.

However the cloud-checksum tool used within the service *is* a tool that
can be run anywhere – and performs a lot of the heavy lifting.

We will need to consider if writing a different copy service for Kubernetes (say), that
would then be the copy service to use for Google. This would only be done were the need to arise.
