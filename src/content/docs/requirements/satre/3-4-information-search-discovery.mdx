  <div class="satre-title">
    <span>🔶</span> 3.4.01 — Changed for Genomics
  </div>
  <p><strong>SATRE (Recommended):</strong> You should provide a metadata catalogue of available datasets for users.</p>
  <p class="satre-context mb-2">Particularly relevant for TREs with population-level data. Access to catalogues should itself be subject to disclosure control.</p>
  <p><strong>Genomics context:</strong> For the thin infrastructure operator model, the data catalogue is a core function of the data layer — it catalogues available datasets and their access conditions, enabling researchers to discover what data exists before applying for access. GA4GH Beacon and similar discovery APIs provide established patterns for genomics data discovery that allow "can I find data matching these criteria?" queries without exposing the underlying data. The catalogue must describe: sample counts, data types available (WGS, WES, RNA-seq), consent scope, and access conditions.</p>
